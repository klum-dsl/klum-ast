# ADR 0014 implementation plan: Groovy 4/5 JPMS boundary

This plan applies [ADR 0014](../adr/0014-groovy4-jpms-boundary.md) for
[#391](https://github.com/klum-dsl/klum-ast/issues/391). It does not preserve
legacy packages, make Groovy 3 named-module use appear supported, or introduce
a general Builder-phase SPI.

## Confirmed starting behavior

- All five KlumAST JARs currently derive filename-based automatic names and
  have no descriptors.
- Compiler and runtime split `com.blackbuild.klum.ast.validation` and
  `com.blackbuild.klum.ast.util.layer3`, preventing module-layer resolution.
- #459 supplies exclusive KlumCast packages and stable automatic names; #461
  supplies the AnnoDocimal 1.0 RC packaging/projection seam. They are inputs,
  not proof of KlumAST module descriptors.
- `JpmsGroovyModuleIdentityTest` proves the Groovy 3/4/5 descriptor boundary
  in all three current compatibility lanes.
- Existing generated-interface, Java/static-Groovy, service, Jackson, Bean
  Validation, and source-mirror tests are classpath evidence only.

## Compatibility and migration constraints

- The five Maven coordinates, BOM entries, and Gradle plugin IDs stay stable.
- Every old package is removed; schemas and clients recompile for 4.0.
- Groovy 3 remains supported on the classpath only. A named-schema attempt is
  a configuration error with remediation, not a test skip or local JVM flag.
- Groovy 4/5 module-path support uses `org.apache.groovy`; both lanes compile
  independent Groovy test sources.
- Generated `Foo_DSL` mirrors remain outside all module/classpath/publication
  inputs under ADR 0005.

## Tracer and implementation slices

### JP-1 — Freeze the package/import inventory

Regenerate the #468 public/member inventory against the chosen base. Classify
every current package/type as exported API, generated linkage, shipped-adapter
linkage, or internal. Produce the complete old-to-new import map, including
generated bytecode descriptors and service files, before moving sources.

**Acceptance:** no target package has two owners; every #468 client,
extension, and generated-hook record has an exported package; every internal
record has an internal destination or a named qualified consumer.

**Commit boundary:** add the map and the verification script/test first. Do not
combine it with source movement.

### JP-2 — Move annotations and runtime to their ownership boundary

Move schema vocabulary to `com.blackbuild.klum.ast`, `.copy`, and `.layer3`;
move all runtime public types to `.runtime`/`.runtime.validation`; and isolate
runtime mechanics under `.runtime.internal`. Update generated descriptors,
services, Javadocs, and Java/static-Groovy consumers together. Preserve the
closed Builder-phase boundary.

**Acceptance:** the annotations/runtime artifacts have no legacy package,
export only their ADR packages, and still pass generated factory, lifecycle,
materialization, validation, and Java/static-Groovy coverage.

**Commit boundary:** one self-contained annotation/public-runtime migration,
then one internal runtime/service migration if they cannot remain green
together.

### JP-3 — Move compiler and adapters; add descriptors

Move compiler implementation into its internal package and create its
Groovy-4/5 descriptor with `org.apache.groovy`. Compiler transformations remain
annotation-triggered local transforms: open `compiler.internal.ast`,
`.ast.converters`, `.ast.mutators`, and `.layer3` to `org.apache.groovy`;
open `compiler.internal.validation` only to
`com.blackbuild.klum.cast.compiler` for the established
`@KlumCastValidator`-based reflective validator binding. The complete
KlumCast-reflected inventory is `FieldAstValidator` in `compiler.internal.ast`,
`WriteAccessMethodCheck` in `compiler.internal.ast.mutators`,
`DefaultValuesCheck` in `compiler.internal.layer3`, and
`CheckDslAnnotation`, `CheckForPrimitiveBoolean`, `OverwriteMapCheck`,
`OverwriteSingleCheck`, and `ValidateAnnotationCheck` in
`compiler.internal.validation`. Therefore `ast`, `ast.mutators`, and `layer3`
also open only to `com.blackbuild.klum.cast.compiler`; `validation` already has
that directive. `ast.converters` remains Groovy-only. These openings are not
exports or generic reflection access. Do not declare a global
`ASTTransformation` provider or export compiler implementation packages. Groovy
3 retains the common classpath artifact with no descriptor alternative. Move Jackson and Bean Validation implementation
linkage to internal packages, retaining only their documented public adapters.
Add exact descriptors, qualified runtime exports to compiler/Jackson only where
bytecode proves they are necessary, and all runtime/Jackson/Bean
`uses`/`provides` declarations.

**Acceptance:** `jar --describe-module` reports the five canonical names and
the intended exports/services; no package is split; no unqualified internal
export exists. A Groovy 4/5 named-module probe activates DSL/mutator, converter,
and Layer 3 annotations without `--add-reads`, `--add-exports`,
`--patch-module`, or equivalent flags; the matching ordinary classpath evidence
remains green in Groovy 3, 4, and 5.

**JP-3b boundary acceptance:** descriptor evidence asserts the complete
compiler `opens` map, including the three KlumCast-qualified validator packages
and the Groovy-only converter package, so a future check cannot widen the
boundary by adding an unqualified open or another target.

**Commit boundary:** compiler descriptor/move, then adapter descriptor/service
work. Each commit retains a buildable descriptor set.

### JP-4 — Execute real named-schema fixtures

Create one real Groovy 4/5 named Schema module and a consumer module. Compile
and run AST transformation, `Foo_DSL` factories, Builder lifecycle and
Materialization, Java and `@CompileStatic` Groovy consumers, PhaseAction and
InstanceValidator service loading, Bean Validation, and Jackson import/export.
Run the equivalent ordinary classpath fixture separately for Groovy 3, 4, and
5. The Groovy 3 named-module fixture must fail with the documented plugin
remediation; it is not an ignored test.

**Acceptance:** all Groovy 4/5 named fixtures pass without `--add-reads`,
`--add-exports`, `--patch-module`, a composite build, or local artifacts.
Classpath fixtures pass in all three lanes.

**Commit boundary:** fixture harness and minimal schema first; service/adapters
as focused extensions with their assertions.

### JP-5 — Validate user-owned descriptors and release guidance

Extend the schema plugin with Groovy-generation-aware descriptor validation.
For Groovy 4/5 it reports missing `requires`, runtime/Jackson `opens`, and
adapter directives with copyable remediation. For Groovy 3 it explains the
classpath-only boundary. It never edits `module-info.java` or adds task-local
flags.

Publish the import map and named/classpath examples in Migration, Getting
Started, requirements, Gradle-plugin documentation, Javadocs, and `CHANGES.md`.
State recompilation and Java-serialization limits. Keep documentation
navigation and the versioned-Javadoc module boundaries current.

**Acceptance:** TestKit exercises valid, invalid, and Groovy-3 schema modules;
documentation has one G4/5 named example, one G3 classpath example, and no
claim that IDE mirrors are module sources.

## Risks and controls

| Risk | Control |
| --- | --- |
| An internal type leaks through a public/generated descriptor. | Regenerate the #468 descriptor inventory in JP-1 and compile named Java/static-Groovy consumers. |
| Service discovery works only from resources on the classpath. | Require descriptor `uses`/`provides` assertions in the named fixture. |
| Jackson needs a different reflection target than runtime. | Fixture both managed import and ordinary export; validate `opens` to Jackson Databind only when applicable. |
| A Groovy 3 module-path workaround silently returns. | Keep the executable negative probe and TestKit diagnostic assertion. |
| Mirror output becomes a duplicate generated API. | Retain ADR 0005's source-set, archive, module, and downstream isolation tests. |
