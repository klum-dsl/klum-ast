## Actual cause and bounded correction

Executing `verifyVersionedDocumentationRenderer` with strict configuration cache fails on both attempts:
**seven execution-time `Task.project` accesses / one unique problem**, followed by
`Task with name 'renderVersionedDocumentation' not found in root project 'klum-ast-root'`.
The original action reaches directory/file reads and deletion (lines 43–46, 59, 94), builds isolated Git fixtures,
renders and verifies them, then tries to discover an unscheduled task through the deserialized Project (line 350).
A successful full-graph dry run cannot expose that action failure.

Ranked hypotheses were directory/file-service calls alone, indirect retention of inspected task models, and incomplete
projection of the verifier's live contract. The causal trace rules out a directory-only correction: the later model
lookups and cross-task state reads also require treatment. Capturing task objects instead is forbidden by Gradle's
[model/task-access requirements](https://docs.gradle.org/8.14.4/userguide/configuration_cache.html#config_cache:requirements:task_access).

The correction uses the established typed-input pattern from the lane-isolation owner:

- Declare current authoring files/assets, README, root/signing conventions, workflow files, landing script and public
  consumer settings as file inputs. Read their current bytes in the action on every invocation.
- Declare inspected dependency paths, discovered Sonatype publication task paths, local-render settings and fail-closed
  publisher description as scalar inputs. Lazy providers project final configured models into values before serialization;
  the action never reads another Task or Project.
- Declare each module's Javadoc output tree and source tree as nested file inputs. Retain source FileTrees rather than
  eagerly capturing filenames, so files generated by prerequisites remain visible during execution. The output location
  accompanies the declared output files; directory lookup alone is not an input substitute.
- Resolve `v3.0.1` to a declared immutable commit identity with `providers.exec`, then read the historical wiki at that
  identity. Changes to the named revision participate in configuration input tracking. Local-render revision settings
  remain declared values and are compared with live `git rev-parse HEAD` during execution.
- Use injected `FileSystemOperations` for the existing temporary-output cleanup.

The task still has **no outputs**, is explicitly not output-cacheable, and executes on both storage and reuse. No
compatibility exemption, warning mode, global configuration-cache setting or dependency weakening is introduced. Seven
Javadoc prerequisites, selection/topology, all fixture checks, negative renderer cases, isolated temporary Git repositories,
deterministic tree digests, HTTP presentation/link crawl and release/workflow diagnostics remain. Default-version and
publication assertions inspect configured values; they do not merely assert hard-coded expected metadata against itself.

## Reproduction and retained controls

From an isolated checkout with Java 17 and frozen HEAD:

```shell
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
python3 docs/implementation/evidence/issue-895-renderer-cache/verify.py
./gradlew -p buildSrc test --no-configuration-cache --no-build-cache --no-parallel --max-workers=2 --console=plain
./gradlew check :klum-ast:annotationPropagationArtifactsGroovy3 :klum-ast:annotationPropagationArtifactsGroovy4 :klum-ast:annotationPropagationArtifactsGroovy5 --no-configuration-cache --no-build-cache --no-parallel --max-workers=2 --console=plain
```

For the negative control, restore only the two owning files from `a15148a8`, append one harmless newline to each so
Nebula still sees the same modified owning paths, run the harness with `--expect-broken`, then restore the correction.
The retained corrected run precedes the original control; both use the same base HEAD, dedicated branch, inferred
uncommitted version, source outside the owner, Java 17, dependency caches and harness. Implementation SHA-256 values
identify the exact source under test. Root HEAD stays frozen; fixture Git commits remain isolated. A fresh explicitly read probe property
selects each pair without deleting existing configuration entries or ordinary execution history. Gradle build-cache
reuse is disabled; `--no-parallel --max-workers=2` bounds work, but configuration cache can enable intra-project execution
independently of that project-parallel flag.

Nebula tracks `StatusPorcelain` as a configuration input. The harness temporarily appends a harmless newline to each
live file used by byte-change controls before healthy storage, keeping the dirty path set constant during rejection and
restoration. Thus the meaningful byte mutations really use the healthy cached configuration. Every original file is
restored in `finally`, including on failure. Temporary workflow mutations are test inputs only and are never committed.
Raw logs/cache reports stay outside the repository; [measurements.json](measurements.json) retains sanitized commands,
log hashes, source fingerprints, task paths, counts and owning source frames. `<probe>` represents a temporary directory.

The 34 corrected invocations include:

- Invalid authored HTML, a README authoring-tree link, wrong pending-workflow name, broken migration-script bracket
  syntax and wrong Plugin Portal consumer repository: each fails with the original diagnostic **while configuration is
  reused**; restoring each file passes with configuration reused.
- Changed documentation version or revision properties: strict storage and reuse both retain their rejection diagnostics.
- Final task-graph configuration removing Maven publication dependencies, exact-render Javadoc dependencies (including
  implicit file-input producer metadata), or pending-stage crawl dependencies, and changing the local-render version:
  strict storage and reuse both reject the actual configured model. These mutations affect unscheduled inspected tasks,
  not the verifier's production graph. The temporary harness callback is not installed in normal builds.
- A prerequisite generates `Probe_DSL.java` after configuration; the source is absent before each invocation, including
  reuse. Both runs reject the generated source mirror. A relocated Javadoc output passes with the original representative
  file absent, proving the configured destination is consumed rather than a hard-coded default path.
- A missing representative Javadoc is rejected on strict storage and reuse. Only this deliberate corruption control
  excludes its producer to prevent Gradle repairing the file first; ordinary and topology controls retain every dependency.
  The exact bytes are restored afterward, and a final healthy store/reuse pair passes with actual renderer execution.

This actual-root harness is the regression seam; copied synthetic wiring would not test task discovery, late root
publication wiring, Nebula invalidation or real Javadoc producers. No new ignored test or generation-sharing shortcut is
introduced. All 15 existing buildSrc regression cases pass with zero failures/errors/skips; ordinary renderer verification also passes.

Early harness drafts exposed legitimate Nebula status invalidation, init-script callbacks applying to buildSrc, root
publication wiring overriding an earlier mutation, an inferred Javadoc input dependency surviving `setDependsOn([])`, and
a final healthy configuration needing storage after property/exclusion changes. They are excluded from the retained pair.
The production correction itself passed its initial executing strict store/reuse; these were probe-assumption corrections.

## Inventory, limits and qualification

Full-graph **serialization** already passed after #909 and still passes: zero problems before and after. The sole observed
**execution** owner was `:verifyVersionedDocumentationRenderer`; it now passes its complete action on strict storage and
reuse. No other owner was observed in these focused/dry-run probes. This is not proof that every task action in a fresh
executing full root check is configuration-cache-compatible; other actions are outside this focused evidence.

Shared macOS arm64 workstation; Azul Zulu Java 17.0.3+7-LTS; Gradle 8.14.4. Existing dependency caches and outputs are
retained. Task compilation/output reuse differs between invocations. These single ordered timings establish functional
cache compatibility, **not a controlled hosted or full-build speedup**. The deliberately live renderer still executes;
its fixtures and crawl are not cached away.

explicit no-child assignment. History review retains one cohesive implementation/regression/evidence reasoning step.
