# Issue #1137: generated helper linkage on release/4.2.x

Date: 2026-11-28

Authority: [#1137](https://github.com/klum-dsl/klum-ast/issues/1137), including the released-4.2.1 evidence comment.
Base: `origin/release/4.2.x` at `c17c90c01a0ff21a41e2bb7de74b3e0f04abf05c`, fetched and verified before branching.
Branch: `codex/1137-jpms-helper-dispatch`. This repair targets only `release/4.2.x`.

## Cause and correction

Generated property setters dynamically called `InternalKlumBuilder.setInstanceAttribute`. Ordinary converters similarly
called `setSingleFieldViaConverter`, `addElementToCollectionViaConverter` and `addElementToMapViaConverter`. Groovy's
MetaClass omits these inherited methods when their declaring runtime-internal package is not exported to Groovy.
The methods exist; the failure is dynamic lookup under JPMS, rather than a JVM missing-method linkage error.

The repair follows the existing fluent-setter/generated-runtime linkage pattern. Four additive protected final hooks in
`GeneratedKlumBuilder` forward to the original runtime methods, and `ProxyMethodBuilder` binds those calls directly.
`PropertyAccessors` uses that generator for both Builder-typed and Model-typed property setters. Converter emission uses
its existing generic proxy route, now bound to the exported generated-runtime base. Existing String/CharSequence hooks
and their argument wrappers remain unchanged. Runtime conversion, overload selection, relationship normalization,
population and mutation/session guards retain their existing implementations.

No module descriptor, public client API, helper visibility, consumer opening, reflection mechanism or lifecycle contract
is changed. ADR 0014 remains the accepted package boundary; ADR 0015 remains Proposed. This work does not modify #1129,
master, an upmerge, release metadata or issue classification.

## Regression seam and TDD

`JpmsPackageBoundaryTest` owns two independent neutral Schema fixtures. Each is compiled through the existing compiler
harness, packaged as a JAR, and run in isolated application JVMs. For Groovy 4.0.32 and 5.0.6 the same Schema JAR bytes
run on both classpath and module path. Groovy 3.0.25 remains classpath-only. Application JVMs exclude the KlumAST compiler
JAR and use no access/read/patch flags. The existing Schema descriptor is sufficient.

The property fixture covers ordinary assignment, an inherited assignment from `@Builder.Method`, a normal fluent setter,
completed-Model LINK assignment, fresh Builder composition assignment, and mutation rejection after session completion
and on a sealed LINK wrapper. The converter fixture covers the original Integer-to-String closure route, numeric List
and keyed Map routes, Integer/Long generated overload selection, zero/multiple arguments, an array argument and a typed
null call through a statically compiled consumer. An expired Builder rejects conversion before factory side effects.
Bytecode guards require direct calls owned by `GeneratedKlumBuilder`, reject dynamic helper bootstrap names and retain
the existing named-Schema prohibition on runtime-internal references.

Each production slice was tested red before implementation and committed green. Before the property repair, G3
classpath passed and G4/G5 named assignment failed with `MissingMethodException: setInstanceAttribute`; before the
converter repair, G3 classpath passed and G4/G5 named scalar conversion failed with the corresponding converter helper.
Matching classpath controls were executed in each red run; the property red run also executed the fluent control. Both repaired slices passed all three targeted
lanes before their commits. Local red XML and command logs are retained at `/private/tmp/1137-*-red*`.

## Retained artifact check and compatibility

The exact released-4.2.1 Schema JARs from the diagnosis were replayed with only the runtime JAR replaced. On G4/G5,
all six classpath calls and both modular fluent controls pass. The four old modular setter/converter calls still fail at
their original dynamic helper names. All 12 outcomes match the expected retained-binary boundary; this does not claim
older generated callers are repaired by a runtime swap. The local matrix, full commands, JAR hashes and output are in
`/private/tmp/1137-retained-binaries/`.

Affected Schema artifacts must be recompiled with the patched compiler and run with its matching patched runtime.
New generated bytecode requires the additive hooks; it is not qualified on an older runtime that lacks them. The repair
neither changes existing public/protected descriptors nor broadens Groovy 3 module support. Qualification covers direct generated Builder converter calls, including the demonstrated scalar/List/Map forms.
Grouped alternative factories and unrelated generated helpers are not included in this bounded repair; no grouped
simple-value collection syntax is introduced. A general JPMS audit, consumer access workarounds, upmerge and release
remain outside this assignment.
