## Delivered qualification

`StructuredScalarAlternativeConsumerTest` follows the independent compiler/JVM packaging pattern of
`RootRecipeConsumerTest` and `GeneratedSchemaProvenanceConsumerTest`, and reuses plugin TestKit's packaged-plugin bridge.
It compiles the neutral four-overload Destination parent, then its child against the parent JAR, then Java, static Groovy
and dynamic Groovy clients against only those JARs and runtime dependencies. Every producer/consumer source and loose
class directory is deleted immediately after packaging. Application JVMs contain neither the compiler nor plugin;
the Java client also checks their implementation classes are unavailable. No fixture depends on ScHelm or Kubernetes.

Each Groovy generation has an actual pre-change binary, compiled by the unmodified compiler at
`d91110749618a6fdb4fa605e128236a57758d3db`, Java 17 / Groovy 3.0.25, 4.0.32 or 5.0.6 / AnnoDocimal 1.0.1.
Those six retained JARs are inputs, never regenerated by the consumer test. They are local builds from historical source,
not claims about historical published coordinates or cross-Groovy binary compatibility. A matching generation proves:

- One marked String route plus an unmarked integer retains String selection and numeric rejection.
- A unique integer operation retains exact numeric conversion and String rejection.
- Unmarked Integer/String collisions remain omitted/rejected.
- A generated Integer converter remains an ordinary helper, not a family arm; Struct and schema retain the String route.
- A new child compiled against a complete parent rejects an unrecompiled historical parent with missing String-arm
  parameter facts, even with an absent payload. It never silently degrades to String or assumes empty constraints.

The same matched parent/child JARs feed actual JSON Schema generation. Assertions check canonical integer/String order,
parent Min versus child Max ownership, inherited Pattern/prose/examples, and unchanged historical single-route output.
Runtime accepts structurally valid values outside the advisory arm constraints; body failure retains its original cause.
The independent Draft 2020-12 oracle uses the shared numeric/type corpus, not handwritten substitute schemas.

Every generation exercises missing-parent, historical incomplete-parent, removed Schema enrichment, removed Operation
fact, removed author mark, wrong operation count and missing parameter-completeness controls. Both runtime (with absent
payload) and TestKit generation reject with the expected diagnostics. Failed generation retains the successful child
schema and complete output manifest. A separate source-free custom-loader control redirects only the parent's public
Builder resource to a decoy JAR: both runtime and the packaged projection engine reject the resource-origin mismatch.
This test-only loader is not an application/runtime extension seam. Existing U1/U2 controls retain protocol, descriptor,
policy, OMIT and malformed constraint-row coverage; U3 does not duplicate that entire matrix.

## JPMS scope and observed limits

Groovy 3 stays classpath-only under ADR 0014. Groovy 4/5 qualify named parent, child and consumer modules with ordinary
`requires`, package exports and declared opens, without `--add-reads`, `--add-exports`, `--add-opens` or patching.
The historical JAR is an automatic module. Java/static/dynamic clients exercise FromStruct, active Builder applyStruct,
integer/String identity, call counts, inherited arm facts and operation-body failure. Source Schema declarations carry
`@CompileStatic`; this is not a claim that every generated helper is statically compiled.

The child's numeric override delegates storage to `super.address(input)`. An earlier probe that directly wrote inherited
fields through generated setters failed on Groovy 4/5 JPMS with `MissingMethodException: setInstanceAttribute`.
Opening Schema packages to Groovy did not repair it. Ordinary numeric calls to the historical generated converter helper
also failed on JPMS with `MissingMethodException: setSingleFieldViaConverter`; that ordinary helper control therefore
qualifies all three classpath lanes, while its unchanged Struct String route and schema also qualify JPMS. These helpers
and the runtime module's internal-package exports predate #1129 and are untouched here. The coarse failed-case logs remain in
`/private/tmp/klum-1129-u3-consumers3.log` and `/private/tmp/klum-1129-u3-consumers4.log`; detailed XML was overwritten
by later successful runs. The exact root causes read from those XML reports during investigation are preserved here:

| Probe | Observed Groovy 4/5 JPMS root cause |
| --- | --- |
| Child body `integerCalls++; value = input` instead of `super.address(input)` | `MissingMethodException: ...Child$Builder.setInstanceAttribute()` with arguments `(String, Integer)` and values `[integerCalls, 1]` |
| Unconditional `Converted.Create.With { address 8080 }` | `MissingMethodException: ...Converted$Builder.setSingleFieldViaConverter()` with `(String, Class, String, Integer)` and `[address, ...Converted$_address_converterClosures, from_Integer, 8080]` |

with the first body above, or remove the `!Converted.module.named` guard around the second call, then run the focused
artifact command below. `consumers3.log` corresponds to the inherited-write body; `consumers4.log` corresponds to the
super-delegating child with the unconditional converter call. Both classpath lanes pass; each named Groovy 4/5 lane
fails with the respective cause above. These are diagnostic probes, not suppressed tests or promised capabilities.
No arbitrary inherited-setter or general converter-helper JPMS support follows from the bounded positive result.

ordinary-Builder limitations warrant separate work; this worker creates no side issue or release gate.
